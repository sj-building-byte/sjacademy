The problem

You knew the answer. The paper didn't.

Most A Level CS students do not lose marks because the topic beat them. They lose them on what the examiner can actually see: a loop bound written on paper with no compiler to complain, a screenshot that never reached the evidence document, an “explain” answered with a description. Examiners mark what is on the page, not what was in your head.

Paper 2 · sample answerScore[1:30] holds 30 marks. Write pseudocode to count the marks above 50.
Above ← 0
FOR Index ← 0 TO 30
IF Score[Index] > 50
Score[0]? the array starts at 1

The loop was off by one

Paper 2 is pseudocode, written on paper. No compiler flags the error, so a loop that starts at 0 when the array starts at 1 looks fine to you. The examiner spots it in seconds.

Paper 4 · sample evidenceRun your program with the test data. Paste a screenshot of the output.
[program code pasted]
[screenshot: missing]
it ran. where's the proof?

The screenshot never made it

Paper 4 is marked from your evidence document. Cambridge is clear that work missing from it gets no marks, however well the program ran on your screen.

Paper 1 · sample answerExplain why a compiler is used before software is distributed. [2]
A compiler translates the whole program into machine code.
that's what. the question asked why

It said what, not why

In Cambridge's command words, “explain” means give reasons. Describing what a compiler does answers a different question, and that question is not on the paper.

None of this means you can't code. It means the examiner never saw it. That part is fixable.

The method

Dry run it like an examiner

There is no computer in the Paper 2 exam room. You run the code in your head and write each value in a trace table. Here is a short loop. One character in it, the < in the WHILE line, decides the answer.

guess first, then run it
Paper 2 style · pseudocodeWhat is output when this runs?
DECLARE Count : INTEGER
DECLARE Total : INTEGER
Count ← 1
Total ← 0
WHILE Count < 5
Total ← Total + Count
Count ← Count + 2
ENDWHILE
OUTPUT Total
< is not <=

What does this program output?

Not quite. 1 is the total after one pass.

The condition is checked again with Count at 3. 3 < 5 is TRUE, so the loop runs a second time.

The output is 4.

The loop runs twice, with Count at 1 and then 3. When Count reaches 5, 5 < 5 is FALSE, so the loop stops before adding it. Total is 1 + 3 = 4.

That is the off-by-one answer.

9 is 1 + 3 + 5, which is what you get with Count <= 5. With <, the loop stops as soon as Count is 5. Step through the trace table to see it.

Trace tables and dry runs are part of 9618 Paper 2. The pseudocode follows the Cambridge pseudocode guide, where ← means “is assigned”.

The syllabus

The A Level Computer Science syllabus (9618), paper by paper

AS Computer Science covers information representation, networks, hardware and logic gates, processor fundamentals, system software, security, ethics and ownership, databases, algorithm design, data types and structures, programming and software development. A2 adds user-defined data types, floating-point numbers, protocols, virtual machines and Boolean algebra, operating systems, encryption, artificial intelligence, recursion and further programming.

AS students sit Papers 1 and 2. The full A Level adds Papers 3 and 4. Calculators are not allowed in any 9618 paper.

Paper 1 · AS LevelTheory Fundamentals

  • 1h 30mduration
  • 75marks
  • 25%of the A Level

What it asks. A written paper on syllabus sections 1 to 8: data representation, networks, hardware and logic gates, processor fundamentals and assembly language, system software, security, ethics and databases. It is 50% of a standalone AS.

What you practise. Exact definitions, binary and hexadecimal conversions by hand, logic circuits and truth tables, and SQL you can write without looking anything up.

Paper 2 · AS LevelFundamental Problem-solving and Programming Skills

  • 2hduration
  • 75marks
  • 25%of the A Level

What it asks. Sections 9 to 12: computational thinking, algorithms, data types and structures, programming and software development. Answers are written in pseudocode, with an insert listing the built-in functions and operators. It is 50% of a standalone AS.

What you practise. Pseudocode to the Cambridge guide, trace tables and dry runs, loops with the right bounds, and test data that is normal, abnormal and extreme.

Paper 3 · A2 LevelAdvanced Theory

  • 1h 30mduration
  • 75marks
  • 25%of the A Level

What it asks. A written paper on sections 13 to 20: user-defined data types, floating-point numbers, protocols, Boolean algebra and Karnaugh maps, operating systems, encryption, artificial intelligence, recursion and programming paradigms.

What you practise. Floating-point conversion and normalisation, De Morgan's laws and K-maps, A* and Dijkstra's searches on a graph, and the theory definitions word for word.

Paper 4 · A2 LevelPractical

  • 2h 30mduration
  • 75marks
  • 25%of the A Level

What it asks. Program code written on a computer with no internet, in Python, Java or Visual Basic (.NET), all in console mode. Your code and screenshots of testing go into an evidence document, and only what is in it is marked.

What you practise. Searching and sorting, stacks, queues, linked lists and binary trees, recursion, classes and objects, file handling and exception handling, all under time, pasting evidence as you go.

How do I get an A* in A Level Computer Science (9618)?

Knowing the topic is half of it. In class you practise past paper questions marked to the 9618 mark scheme until those habits are automatic.

What is the difference between AS and A2 Computer Science?

AS Level is Papers 1 and 2: theory fundamentals, and problem-solving written in pseudocode. A2 adds Paper 3, advanced theory, and Paper 4, a practical programming paper taken on a computer. We teach the full 9618 syllabus for both.
